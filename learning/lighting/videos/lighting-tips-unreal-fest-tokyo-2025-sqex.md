## 概要

写真業界のデジタルカメラ登場（2000年頃）とCG業界のUE5 Lumenリアルタイムグローバルイルミネーション実装（2020年頃）を「その場で結果が見える」という共通点でパラダイムシフトと位置づけ、**実務経験値より光に対する感性・審美眼が問われる時代になった**という主張が全体を貫く。5章構成＋Lumen Hit Lightingのコラム。

## 第2章：光を観察する（考え方の核）

- 問題提起：CGアーティストはキャラクター・背景は観察するが光を意識しない
- 絵描きの着目点（輪郭・形状・粒模様）とライティングアーティストの着目点（光の方向・ハイライト・シェーディング境界・照り返し・明暗比）を対比
- **ライティングハント**：「光が芸をしているシーンをスナップする」実践法。街に出て光の良いシーンを撮る、UE5内でもスクリーンショットを撮る。推奨環境はHillside Sample Project
- 観察から得た発見：夕方の傾いた光の方がドラマチック／天井シーリングライトは平面的で退屈／窓際スタンドやテーブルライトで雰囲気向上／窓外の怪しげな光で映画的に
- 印象の言語化：「漠然とした記憶」を「煌びやか」「情緒的」「怪しげ」「不気味」「静寂」「硬質」等のキーワードに変換するプロセスを推奨

## 第3章：UE5でのライティングのヒント（実装Tips）

| # | 手法 | 内容 | ページ |
|---|---|---|---|
| 3-1 | 練習場所の選択 | 日中屋外は避け、夜間・室内・無機的空間を推奨（太陽光固定で発見が少ないため） | - |
| 3-2 | **Exposureロック**（p.22） | Min EV100とMax EV100を同じ値に設定しAutoExposureを無効化。明暗はライティングの重要要素なので固定して確認する | p.22 |
| 3-3 | WhiteBalance戦略 | WhiteBalanceはデフォルト維持し、**シーンの色はライトの色そのもので作る**（PPVのTemperatureに頼らない） | - |
| 3-4 | ライトPivot設定 | PivotOffsetをx方向100〜300程度、対象（キャラの胸あたり等）に配置。光の方向制御が「非常に楽になる」 | - |
| 3-5 | **光の質（SourceRadius）**（p.26-27） | SourceRadius 5＝硬い光、SourceRadius 80＝柔らかい光。狭い範囲→硬い光、広い範囲→柔らかい光という基本原理 | p.26/p.27 |
| 3-6 | 光の流れ作成 | Pivotを基に複数ライトを円環上に複製し、Intensityを徐々に弱化させ方向性のある光を再現 | - |
| 3-7 | 光の色・光質のバリエーション | 同じ設定のライトをそのまま複製しない。色・サイズを毎回変えることで「複雑で表情豊かな自然なシーン」になる | - |
| 3-8 | 光のカット（引き算） | 黒い板で光を遮る「黒で締める」高等技法。光の足し算だけでなく引き算も重要 | - |
| 3-9 | トーンマッピングとの関係 | ライティングバランスはトーンマッピング（OriginalLUT/NoToneMap/FilmicToneMapper）で大きく変わる | - |

## 第4章：作業の心得（ワークフロー）

1. **目標キーワードのリスト化**：どんな雰囲気にしたいか（例：「夜の雰囲気」「街灯は冷たく建物は暖色」「寂しく暗い雰囲気」）を先に言語化
2. **クオリティアップ項目のリスト化**：綺麗に/印象的に/立体的に見せる、主題を強調する、等の向上軸を整理
3. **セルフリテイク**：前後の流れに最適化できているか／目標キーワードに沿っているか／ライティングが目立ちすぎていないか／美しい印象か、を自己確認し妥協せず反復（Take1→リテイク→Take2→リテイク→Take3の反復フロー）

## コラム：Lumen Hit Lighting（UE5.5以降の新機能）

- 従来の制限：スケルタルメッシュ（キャラ等）は周囲GIから影響を受けるが、周囲に影響を与えられない
- 新機能：**Ray Lighting Mode を Hit Lighting に設定**することで、PathTracingと遜色ないGI効果が得られる（従来はProjectDefault=Surface Cache）
- ※独立再取得で確認したところ、「RayLightingMode=HitLighting」という厳密なパラメータ表記ではなく「Ray Lighting Mode Hit Lighting」という文言に留まる（p.25）。プログラム的な設定パス（プロジェクト設定かLightコンポーネントかコンソール変数か）はスライドから断定できず、実装時に現物確認が必要

## 監査（ペア照合）

1. SourceRadius 5=硬い光／80=柔らかい光（p.26/p.27）— 一致
2. Exposureロック（Min EV100=Max EV100設定）（p.22）— 一致
3. Lumen Hit Lighting のパラメータ表記 — **やや曖昧**（「Ray Lighting Mode Hit Lighting」という文言のみで、正式なコンソール変数/プロパティ名としての厳密表記は確認できず）

## SCRAP BLITZ UE への応用メモ

- **Exposureロック（3-2）**とSourceRadius（3-5）は、既存の[lighting-overview-and-mobility.md](lighting-overview-and-mobility.md)（Light Type5種/Mobility3状態）と直接組み合わせられる実践的パラメータ。ステージのライティング調整時にすぐ使える具体値
- **「黒で締める」（3-8）**は、既存の背景演出方針（Stage3のネオン柱・発光球体等の強い光源）とのコントラスト管理に応用できる考え方。強い発光要素を活かすには、周辺を意図的に暗くする工程が必要という示唆
- **Lumen Hit Lighting**：本プロジェクトはUE5.8を使用しておりHit Lighting自体は利用可能なはずだが、パラメータの正確な設定パスは未確認。キャラクター（METEO等）が周囲環境に影響を与える表現をしたい場合の候補として記録
- **セルフリテイクのワークフロー（第4章）**は技術的な実装項目ではないが、演出調整時に「目標キーワード→リテイク」というチェック手順として流用できる考え方
