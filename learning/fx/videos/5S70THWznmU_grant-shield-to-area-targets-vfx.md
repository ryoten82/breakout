## 概要

前作で作ったシールド VFX（生成・被弾リアクション・破壊）に、①被弾回数に応じて成長する「ひび割れ」ディテール、②複数対象（範囲内の味方全員）へのシールド付与、の2つを追加する回。前半はマテリアル・Niagara 側のひび割れ実装、後半はブループリント側のロジック（単体付与→複数対象への拡張）が主題。

## 技術詳細

### 1. ひび割れマテリアル（クラックレイヤー）

- ベースのシールドマテリアルを複製し、クラック用テクスチャを Opacity と Emissive Color の両方に接続
- TexCoord ノードでタイリング制御。**Index 0 と Index 1 の使い分け**: Index 0 は各六角形パネル共通の UV（全ヘックスが同じ模様になる）、Index 1 はメッシュ全体を貫通する UV（ヘックスごとに模様が変わる）。ひび割れは「反復感を消したい」ため Index 1 を採用
- ランダム回転: X/Y を Append Vector でまとめ、Rotator ノードの Time 入力にランダム値を接続して回転をランダム化
- タイリング密度: デフォルト X/Y = 3（密度を上げるため）
- `1 - x` で反転してひびを可視化 → Power ノードで強度制御 → **Divide（定数20 ÷ パラメータ値）** で「被弾回数」と「ひびの濃さ」を対応づけ（パラメータ1=ほぼ見えない、2=薄く見える、3=はっきり、4-5=かなり濃い、という体感カーブが動画内で明言）
- ひびの結果を自分自身に掛け合わせる（自己乗算）でコントラストを強調。さらに Time × Sine で明滅させ動きを出す（Sine の乗算係数=2、完全に消えないよう下限を残す調整）
- Emissive では Particle Color を乗算して色を統一。ひびの色強度はシールド本体エッジより弱くすべき、という判断で **×0.1** を追加乗算

### 2. Dynamic Material Parameter のインデックス管理と「設定タイミング」の罠 — 本ノートの核心

- ベースシールドの共通 UV パラメータが Dynamic Material Parameter の Index 0 を占有済みのため、クラック用の4パラメータ（intensity / tiling / UV / rotation）は **Index 1** に新規追加
- **重要な失敗→修正パターン**: これらのパラメータを Particle ステージの Dynamic Material Parameters モジュールで直接ランダム設定すると、**パーティクルがスポーンするたびに**タイリング・回転がランダム化され、メッシュ全体でバラバラの模様になってしまう（動画内で実際に失敗例を再現して見せている）
  - 修正: **Emitter パラメータ**として Float（X, Y, rotator）を新規作成し、値を Emitter Spawn の段階で一度だけ設定 → Particle ステージの Dynamic Material Parameters モジュールはその Emitter パラメータを参照するだけにする
  - 結果、値は「その Niagara システムが生成されている間ずっと一定」になり、次にシステムが再スポーンされるまで固定される
- ひびの強度（被弾回数連動）は Emitter/Particle レベルではなく **User Parameter（Integer, count, default 0）** として公開し、ブループリント側から `Set Niagara Variable (Int)` で書き込む。この際「**Set Active（リセットせずに）**」を使うことで、システムを再起動せずリアルタイムにパラメータだけ更新する

### 3. シールド破壊エフェクトの分離

- 新規 Niagara System を作成し、持続シールドの「End」系エミッタ（消滅時演出）だけを複製して流用
- 複製したエミッタは Spawn Time やループ関連の設定が不要なため無効化し、「トリガー時に一度だけ再生される」システムに変換

### 4. ブループリント側フロー（単体付与）

- `Spawn System Attached` でキャラクターのコンポーネント（カプセルコンポーネント）にシールドを追従スポーン
- **既知の事故パターン**: Begin Play 内で「アタッチ先コンポーネント」変数をスポーンと同時に渡すと、シールド側の Begin Play 実行タイミングと値の書き込みタイミングが競合し、正しくアタッチされない（Delay を挟んで解消。動画内でも「実プロジェクトでは Begin Play に直接スポーンを置かない設計にするので本来起きない事故」と補足あり）
- シールドのスポーンタイミングはキャスト（詠唱）アニメーションの終了（約0.7秒後）に合わせて Delay で調整
- Impact（被弾）はカスタムイベントとして実装。呼ばれるたびに①Impact Niagara をアタッチ先にスポーン、②count 変数をインクリメント、③count が閾値（例: 5）以上なら両方の Niagara コンポーネントを Destroy して破壊エフェクトを attached でスポーン、未満なら `Set Niagara Variable (Int)` で count を Loop Shield システムに渡してひびを進行させる
- シールド持続時間はデフォルト5秒、テスト時は15秒に変更（Niagara 側 or ブループリント側どちらでも設定可能な作り）

### 5. 複数対象（範囲内の味方）へのシールド付与

- 単体用のロジックをそのまま流用し、キャラクターブループリントに **Box Collision コンポーネント**を追加して「範囲」を定義
- `Get Overlapping Actors`（クラスフィルターで AI/味方クラスを指定）→ `For Each Loop` で範囲内の各アクターに対して、**単体付与と同一のシールド生成ロジックを1体ずつ繰り返す**（Attach To Component は各アクターの Root Component、位置は Get Actor Transform）
- 範囲内に入ってきたキャラクターにも動的に反応してシールドが付与される（トリガーボリューム的な挙動）
- 各シールドは付与されたアクター単位で独立した Niagara コンポーネント・独立した count 変数を持つため、被弾・破壊は完全に個別制御できる（1体だけ被弾させても他のシールドはひびが入らない、と動画内で確認）

## 新規性のある技術情報（既存ドクトリンとの比較）

`fx_technique_doctrine.md` には「大量イベントFX」を Niagara Data Channel（NDC）で1システムから多数のパーティクルへブロードキャストする手法が載っているが、本動画の「複数対象へのエフェクト付与」は**まったく異なる設計**であり新規:

- **NDC ではなく「アクター単位のループ生成」パターン**: 範囲内の対象は Blueprint 側で `Box Collision` の `Get Overlapping Actors` → `For Each Loop` で列挙し、対象1体ごとに独立した完全な Niagara System（自前の count・自前のひび進行・自前の破壊トリガー）をアタッチスポーンする。1つの Niagara システムが多数の対象を内部で捌くのではなく、**「1対象=1システムインスタンス」を N 個並べる**設計。パーティクル大量発生系（NDC 向き）と、少数〜中量の独立した「効果を持つオブジェクト」の複製（この動画の設計）は別カテゴリとして区別すべき、という実例
- **Dynamic Material Parameter の設定ステージ問題**（Emitter Spawn で一度だけ設定 vs Particle ステージで都度ランダム化）は既存ドクトリンの「値の設定と評価モジュールは分離」原則と同系統だが、「メッシュ全体で模様を統一したいときは Particle ステージでなく Emitter パラメータ経由にする」という**具体的な失敗→対処の実例**は未収録
- **TexCoord Index 0（パネル単位共通 UV）と Index 1（メッシュ全体通しの UV）の使い分け**でリピート感を消す手法は既存ドクトリンに記載なし
- **Divide(定数 ÷ パラメータ) でヒット数と視覚強度を対応づける**カーブ設計（20÷N）は、既存ドクトリンの「グロー勾配: 1-xでなくDivide(小値)」節と同系統の応用例として追記候補
- **User Parameter + `Set Niagara Variable` + Set Active（リセットなし）** でシステムを再起動せずにライブでパラメータだけ更新する運用は、既存ドクトリンに明記なし（Dynamic Material Parameterの動的化はNormalizeAge基準のFloat from Curveという別手法が既存記載）

## SCRAP BLITZ UEへの応用メモ

- METEO やパートナーキャラの「味方援護技・バリア技」（範囲内の味方全員にシールドを付与する OC/SP 技）は本動画の構成とほぼ1対1で対応する。実装方針として、**Niagara 側で複数対象をまとめて処理しようとせず**、対象検出（オーバーラップ/範囲判定）はゲームプレイ側（UE では Overlap イベントや範囲コンポーネント）で行い、**対象1体につき1個のシールド Niagara コンポーネントをアタッチスポーンする**設計を踏襲するのが素直
- ひび割れ演出（被弾回数で段階的に劣化する見た目）は、SCRAP BLITZ の**バリア/ガード技の耐久値可視化**に転用できる。User Parameter（Int）でヒット数を持たせ、Blueprint/GA 側から都度書き込む構成は、UE の GameplayAbility 側のダメージイベントと相性がよい（`Set Niagara Variable` 相当を GA の OnDamage フックから呼ぶ形）
- Dynamic Material Parameter を「Emitter Spawn で一度だけ設定」するテクニックは、OC ジェムや既存の Niagara アセットでランダム回転/タイリングを持たせつつ「1体の中では模様を統一したい」ケース全般（例: 複数の装飾パーツを持つエフェクトで、パーツごとに個体差を出しつつ内部は統一したい場合）に転用余地がある
- 破壊エフェクトを「持続エフェクトの End 系エミッタを複製して単発化する」手法は、SCRAP BLITZ の既存 AOE テレグラフ資産（SBMine 型）が持続→終了の2段構成である場合、終了演出の使い回しパターンとして参考になる
