## 概要

放射状に分割された専用シリンダーメッシュ（10 行×10 列相当の矩形＝ピクセルが並ぶ形状、Patreon 配布の外部モデル）を土台に、ノイズテクスチャ由来のオパシティとグリッド柄のエミッシブカラーをマテリアルで組み合わせ、SF・ホログラム的な「矩形が明滅しながら組み上がる」見た目を作る。Niagara 側はこのメッシュを大量スポーンする本体エミッタに、火花的な副エフェクトを追加して完成させる。

## マテリアル構築

### 前提：専用メッシュ
- 通常の UE 標準ツールでは作りにくい「放射状スライスを持つシリンダー」を使用。動画製作者の Patreon で無料配布されているスタティックメッシュを流用する方式（UE 内蔵ツールでの自作は困難、と明言）
- このメッシュは 10 行×10 列相当の矩形マス目に分割されており、以降のテクスチャ・UV 設計はすべてこの「10」という分割数に合わせて作られる

### Opacity チェーン
1. ブレンドモードは半透明系（Translucent、シェーディングは Unlit 系 ※推定、詳細な設定手順は字幕からは断片的）
2. ピクセルノイズテクスチャをサンプルし、パラメータで乗算した後、**別パラメータで Floor 除算**（`floor(x * param) / param` 相当の量子化）してグリッド状の段差を作る。このパラメータは `10` に固定 — メッシュの行列数（10×10）と一致させるための値
3. Panner でテクスチャをスクロール
4. Dynamic Material Parameter を2つ使用：Param1 は "Random" にリネーム（前作動画で「Particle Random Value ノードで Param1 の代用が可能」と言及したとのコメントあり）、Param2 は "Noise Power"。Panner の速度に Weight 0.2 を設定
5. Particle Color の Alpha チャンネルを減算し、`1 - x` を追加
6. マスク形状として Box Mask 2D を使用（円形版の Sphere Mask も選択肢として言及）。TexCoord に 10 を乗算、B 値 0.5→0.8 に調整、`1 - x` を挟んで明部を反転（「明るい方を中心にしたい」という意図）。さらに別のマスクで L/B=2、A=0.1 相当のパラメータを設定
7. 上記マスクとノイズテクスチャを乗算し、Depth Fade を加算して Opacity 完成

### Emissive チェーン
1. 別のカラーグラデーションテクスチャ（8 行×列構成）をサンプル。10 行グリッドに揃えるため UV の U スケールを `1.25` 倍
2. Panner でスクロールさせるが、単純な速度指定では「ピクセル単位の移動」と噛み合わないため、**Time ノード → Floor → Panner の Time 入力に接続**という構成にする。これにより「1グリッド分だけ一気に進む」離散的な移動（コマ送り的なグリッドスナップ）になる。Panner 内の速度は 2 倍
3. U 方向を 1.25 倍スケールした影響で速度もスケールがずれるため、Panner 速度側に `0.125` または `0.25` の補正係数を追加で乗算（※推定・どちらの値か字幕から確定不可）
4. 最終的に Particle Color を乗算して Emissive Color として出力

## Niagara システム構築

### メインエミッタ（グリッドメッシュ本体）
- Emitter State: Loop Duration `0.2`、Spawn Rate `1000`
- Mesh Renderer: 上記の専用シリンダーメッシュ + 今回作ったマテリアル
- Particle Spawn:
  - Lifetime: Random `1〜2`
  - Color: 前工程からコピー
  - Mesh Mode/Orientation 関連パラメータ: Random Uniform `3〜8`（※推定、対象パラメータ名は字幕から特定できず）
  - Dynamic Material Parameters: Random = `0〜1`、Power = `1〜3`
  - Shape Location: Cylinder、Height `1000`、Radius `0`、Offset Mode = Default、Z 軸オフセット `500`（※推定）
  - Initial Mesh Orientation: X 軸のみ Rotation `0〜1`（前段のコピー値を流用）、Rotation Rate は前段より速く `1` に設定
- **UV グリッド整合のための量子化トリック**: Preview 上で矩形が不完全に見える問題に対し、Sprite/Mesh の UV オフセットを `Floor(Float * Int)` で構成（Float = `0.1`、Int = Random `1〜10`）。10 種類の離散値のどれかにスナップさせることで「ランダムだがグリッドからはみ出さない」オフセットを得る
- Scale over life は Curve（テンプレートカーブ、最大値 `0.6`）で抑制し、プレビューで明るすぎた問題を調整

### 副エフェクト（火花的な追加パーティクル）
- 同システム内に追加した別のパーティクルグループ・emitter（詳細な追加方法は「もう一つ effect を足す」としか言及されず、既存エミッタ内の追加モジュールか新規エミッタかは字幕から断定不可 ※推定）
- Lifetime: `0.5〜1`
- Mesh Scale Mode: `10〜15`
- Shape Location: Height `100`、Width（Of Side）`100`
- Spawn Rate: `500`
- Color Scale Alpha 最大値: `0.4`
- 調整の結果、Lifetime を `2〜4` に延長して見た目を改善（動画内の最終確認で「良くなった」とコメント）

## 新規性のある技術情報（既存ドクトリンとの比較）

`fx_technique_doctrine.md` および既存ノート（[58RyWzN8O84_magic-portal-vfx.md](58RyWzN8O84_magic-portal-vfx.md) の「ノイズテクスチャをピクセル化」パターン）と比較して、以下が未収録・別軸の新規パターン：

- **専用メッシュ側でグリッド分割済みの「ピクセル」を作り、マテリアル側は Floor 量子化だけで済ませる設計**: 58RyWzN8O84 はテクスチャ側の組込み Pixelate 関数でグリッド化していたのに対し、本動画はメッシュの物理分割（放射状シリンダー）とテクスチャの Floor 量子化を両輪で使う。メッシュ側で分割を担保することで UV 精度に依存しない安定したグリッド境界が得られる、という設計判断が透けて見える
- **Panner の Time 入力に `Floor(Time)` を接続してグリッドスナップ移動を作る**: doctrine 既存の「Panner の Time 入力に Radial Gradient + Time を接続して疑似渦を作る」（[h-gp4l1oIbU_portal-vfx.md](h-gp4l1oIbU_portal-vfx.md)）と同じ「Time 入力を直接加工する」発想の別応用。あちらは連続的な歪みだったのに対し、こちらは **離散的なコマ送り移動**を作るための量子化という点で新規
- **`Floor(Float × Int(Random))` によるパーティクル単位の離散 UV オフセット**: 連続乱数ではなく「N 種類のグリッドセルのどれか」にスナップさせるためのパターン。ランダム性をグリッド境界内に強制収束させる汎用テクニックとして doctrine のマテリアル定型節に追記候補

## SCRAP BLITZ UEへの応用メモ

- **敵/ボスの実体化・分解（マテリアライズ/デマテリアライズ）演出**に直結しやすい構成: グリッド状に明滅する矩形パーティクルが積み上がっていく見た目は、「デジタル的に組み上がって出現する」「破壊時にピクセル状に崩壊する」ボス演出・雑魚敵の召喚演出のどちらにも転用できる
- **専用メッシュ＋Floor 量子化という設計判断**は、既存の OC ジェムや Sparkle ビルボード系の反復作業（`handoff_scrapblitz_2026-07-09_ocgem-vfx-billboard-bug-and-pacing-concern.md` 参照）に対する一つの示唆になりうる: テクスチャ側のマテリアルロジックだけで頑張るのではなく、**メッシュ側の形状で構造を先に確定させてからマテリアルを軽くする**という順序が、繰り返しの往復を減らす設計指針として応用できる可能性がある
- **離散スナップ UV オフセット（`Floor(Float × Int)`）** は、道具箱として汎用性が高い。ランダムだが規則的なグリッドに沿ったバリエーションが欲しい場面（例: 複数の矩形/タイル状破片が同時に明滅する演出、SP ゲージ周りのデジタル風エフェクト）に転用余地がある
