## 概要

3D メッシュを回転させずに、マテリアルのみで「板が横方向にパタパタとフリップする」ような疑似回転演出を作る手法の応用編。前作では左右方向への単純なフリップのみだったが、本動画では**上下端に歪み（縦方向の変形）を追加**し、フリップの説得力を高める。設定は前作同様マテリアル内で完結し、Blueprint 側は制御パラメータの Timeline 駆動のみ。

## 技術詳細

### 1. 前作の振り返り（水平フリップ・簡略）

- UV の U 方向に「horizontal gradient multiplier」を乗算し、左から右へ段階的にフリップが進行する見た目を作る
- セグメント数（例: 20）を増やすほどフリップの粒度が細かくなる。20 セグメント設定時、効果は概ね `-10` 付近で完全に消える、という目安が示される（※推定：具体的な数値の意味は前作依存で本動画では簡略説明のみ）
- Blueprint 側でこの値を `-10 → 0` へ非線形に推移させる。**線形カーブは不可**（マスク値はゲート方向の gradient multiplier に対してほぼ指数的に増加するため、早く立ち上がって後半で減速するカーブが必要、とだけ説明）

### 2. 上下端デフォーメーションの追加（本動画の核心）

タイル分割の作り方を変更する：
- TexCoord の **U 方向のみ**タイル数（例 20）を乗算 → frac でタイル分割
- **V 方向は乗算せず**、V からのみ `0.5` を減算 → ピボットを `(0, 0.5)` にシフトし、各タイルの正しい回転中心を作る
- **CustomRotator** ノードでこの TexCoord を回転。RotationAngle には Material Parameter Collection の `rotate` パラメータを接続
- 回転後の TexCoord から **G チャンネル（=V 方向）のみをマスク**として抽出
- 絶対値化 → `1 - x`
- **Power ノード**でエッジのフォールオフを強調
- **Saturate** で 0-1 にクランプ
- そこから `0.1` を減算。これは後続で floor/ceil 的な二値化を行う前提の下駄履かせで、「先に何か値を引いておかないと領域全体が 0 か 1 のどちらかに潰れてしまう。これによりエッジ領域と中心領域を区別できる」と説明される
- 結果として得られる**回転済みマスク**は「見た目は平行四辺形だが、実体は UV 境界に制約された通常の矩形」（もっと厳密な数式で真の平行四辺形を作ることも可能だが、本動画は最もシンプルで直感的な方法を採用、と明言）
- この回転マスクを元のタイル矩形形状と**乗算合成**すると、フリップ時に上下端が歪む見た目が生まれる
- 最終的に Emissive Color に接続

### 3. Blueprint 側のパラメータ駆動

- MPC の `rotate` スカラーパラメータを参照し、Timeline でその値を制御
- 正負の符号がフリップの左右方向を切り替える
- ループは `0.03 → 0`（0 から 0.03 ではなく、0.03 から 0 へ）に設定する必要がある、と実演中に修正が入る（初期実装では lerp の A/B が逆で動きが不自然だった）
- 再生速度は Niagara/Blueprint コンポーネント内の Timeline の Play Rate（例 0.5 や 0.25）で調整

### 4. マスクによる表示範囲変化への対応

- マスクを適用した結果、表示領域がテクスチャ全体でなくなるため、Blend Mode を **Masked** に変更し、**Scale UV by Center**（X=1, Y=0.8 目安）でテクスチャのスケールを補正
- 加えて Blueprint 側でメッシュのスケールも調整し、全体が正しく収まるようにする

## 新規性のある技術情報（既存ドクトリンとの比較）

`fx_technique_doctrine.md` v2.4 の「UV制御は1関数に集約」節は Panner→Add(Offset)→CustomRotator(RotationAngle) という**パン用**の定型パターンとして CustomRotator に既に言及しているが、本動画の使い方はそれとは目的が異なる：

- **CustomRotator を「見た目のテクスチャ移動」ではなく「タイル単位のマスク形状そのものを回転させて疑似 3D フリップを作る」用途に転用**する手法（回転後の V チャンネルを abs→1-x→Power→Saturate で加工し、回転済み矩形マスクを平行四辺形に見せかける）は既存ドクトリンに未収録の新規パターン
- **タイル分割時に U/V で異なる処理を適用する**（U のみタイル数倍、V のみ 0.5 減算してピボットシフト）という、フリップ演出特有の非対称 UV 加工も新規
- **メッシュを一切回転させず、マテリアルのマスクだけで 3D 回転の錯覚を作る**という設計思想自体が、既存ドクトリンの「1粒バースト+カーブ駆動の器」（メッシュ/Light/Decal 中心の軽量化パターン）とは異なる**マテリアルのみでの疑似アニメーション**という軸で新規性がある

## SCRAP BLITZ UEへの応用メモ

- **アイテムのキラキラ/回転演出**: OC ジェムやピックアップアイテムの「くるくる回転して光る」表現は、現状 Niagara の Mesh Renderer での実回転か、ビルボード常時正対に頼っている（`iDrsEp3AGWA_magic-orbs.md` 等）。本手法のような「マテリアルのみでフリップの錯覚を作る」アプローチは、真の 3D 回転メッシュを使わずに軽量な板 1 枚で同様の「表裏が切り替わる」視覚効果を出せる可能性があり、Draw Call/ポリゴン数を抑えたい大量ドロップ演出（Crate/GasCanister ドロップ品など）に向く候補
- **被弾/回避演出への転用は限定的**: 本手法は「ゆっくり進行するフリップ」を前提としており、STREAK やコンボ等の高速演出には向かない。むしろ「アイテムが待機中に緩やかに回転して目を引く」常時装飾レイヤー向き
- **注意点**: 本手法は Blend Mode = Masked + Scale UV by Center によるテクスチャ補正が必須のセットで、これを忘れると表示崩れが起きる（動画内でも実演中に一度ハマっている）。導入する場合はこの補正込みでテンプレ化すべき
- 前作（水平フリップのみの基礎版）が学習部屋に未収録のため、実装時は前作相当のロジック（水平フリップのタイル分割・非線形カーブ駆動）を本ノートの記述から逆算するか、別途前作を追加学習する必要がある
