## 概要

Niagara の Sprite Material 用に、テクスチャに頼らず TexCoord のノード演算だけで「三角形」「矩形」「円」の 3 形状マスクを作る短いチュートリアル。作った形状はパーティクルカラー・エミッシブと組み合わせ、最後に Niagara の Sprite Renderer（Color Mode = Random Hue）で表示確認する。初学者向けの基礎シェイプマテリアル講座。

## 技術詳細

### 三角形（簡易版）

- TexCoord → Mask で R, G の 2 チャンネルを取り出し、そのまま Subtract（R - G）するだけで粗い三角形状のマスクが得られる（欠けた片側だけの簡易ウェッジ形状）

### 三角形（中心制御版・本編の主題）

1. TexCoord をコピーし、UV の中心が原点になるよう再センタリング： `(TexCoord - 0.5) * 2`。Constant Bias Scale（Bias = -0.5, Scale = 2）でも同じ結果になると明言（等価な2手法として紹介）
2. R, G 各チャンネルに **Absolute** を適用し、両者を **Add**
3. **1 - x（One Minus）** で値域を反転（中心が高く、周辺に向けて 0 に近づく形に整形。※推定：正確な値域遷移はASR上「0 to one back to zero」という表現で、字幕から数式の完全な再現はできず、実装時は実機再現で確認要）
4. 同様の処理をもう一系統作り、両者を **Subtract** することで三角形のシルエットが得られる
5. **高さ制御**: Subtract の前段に別の Multiply を挿入することでパラメータ化
6. **位置制御**: 同様に Subtract ノードを追加してオフセット制御
7. **二値化（0/1マスク化）**: 「値が 0 より大きい場合は出力 0、0 以下の場合は出力 1」という閾値変換ノードを追加してエッジをシャープなマスクに変換（※推定：字幕上「Type To Zero」という表現で正式なノード名が特定できず。UE標準ノードでの正確な名称は実機確認が必要）

### 矩形

1. 上記の再センタリング+Absolute の2ノードをコピー
2. 各チャンネルから任意の定数（エッジ半径パラメータ）を **Subtract** して、中心=0・エッジに向かうほど値が大きくなる分布を作る
3. **Length ノードで2チャンネルを1チャンネルにマージ**する前に、**各チャンネルを 0 と Max 比較**（负值を 0 にクランプ）する下処理が必須と明言 — Length は内部で二乗計算をするため、クランプせずに負値を含めたまま渡すと符号が失われ、本来暗いはずの中心が誤って明るい大きな値になるバグが発生する、と実演で明示的に指摘されている（**Length ノードへの入力は事前に Max(x, 0) でクランプする**、という具体的な落とし穴の指摘は既存ドクトリンに未収録）

### 円

- Radial Gradient を半径違いで2つ用意し Subtract するだけのシンプル構成
- Density パラメータを大きめ（25 程度）にすることでエッジをシャープにする、と説明

### 仕上げ・応用

- 背景の黒領域にも薄く色を持たせたい場合、Lerp で B=5, A=0.02 程度を追加（※推定：数値はASR誤認識の可能性）した上で、**形状マスクと乗算**しないと黒領域全体に色が回ってしまう問題があると指摘 — 「形状マスクをそのまま最終合成に使うのでなく、周辺の薄い発色にも同じマスクを再度乗算する」という二段階マスク適用の注意点
- Particle Color の A チャンネルを形状マスクに乗算し、RGB チャンネルを Emissive Color に接続する定型
- **「目」のあるキャラクター的三角形**: 三角形ノードをコピーし、UV を中心基準でスケール（0.8）+ Saturate した縮小三角形を作り、オリジナルの三角形から Subtract することで内側に「目」のようなくり抜き模様を作るテクニック。位置がズレる場合は縮小三角形側のオフセットパラメータで微調整
- 作者コメント：この手法は「クルード（粗い）」なマテリアルであり、マスクやパーティクルエフェクト用途には十分だが、高精度な三角形が必要な場合は専用の SDF 系マテリアルライブラリ（※推定：具体的な製品名は ASR 誤認識のため特定不能。「project for... plus... material library... free」という趣旨の言及のみ）を推奨、としている

### Niagara 側の設定（簡易）

- 作成した図形マテリアルを Sprite Renderer に割り当て
- **Color Mode = Random Hue**
- **Hue Shift Range = -1 〜 1**
- **Scale Color RGB = 10**（発光を強めるための乗算値）
- **Scale Color with Size = 2**（サイズに応じた色スケーリング。※推定：正確なパラメータ名はUE実機で要確認）

## 新規性のある技術情報（既存ドクトリンとの比較）

`fx_technique_doctrine.md` のマテリアル定型節はテクスチャ＋Particle Color の乗算構成が中心で、**テクスチャを使わずノード演算のみで幾何形状マスク（三角形/矩形/円）を作る手法**は未収録。以下が新規:

- **TexCoord の再センタリング（`(uv-0.5)*2` または Constant Bias Scale）+ Absolute + Add + One Minus + Subtract** という一連の演算で三角形シルエットを構築するパターン。ドクトリンの Radial Gradient ベースの円形マスク定型とは別系統の、直交座標ベースの SDF 的アプローチ
- **Length ノードへの入力は事前に `Max(x, 0)` でクランプする**という具体的な落とし穴。二乗演算を内部で行う Length ノードに負値を渡すと符号情報が失われて中心が誤って明るくなるバグを実演で明示している点は、ドクトリンのどの節にも記載がなく新規
- **形状マスクの二重適用**（背景の薄い発色にも同じシルエットマスクを再度乗算しないと、黒背景全体に色が回ってしまう）という合成順序の注意点
- 図形の内側を別図形の Subtract でくり抜く（「目」パターン）という、形状同士の差分合成によるディテール追加の設計パターン

## SCRAP BLITZ UEへの応用メモ

- **基礎図形の組み合わせによる汎用エフェクトパーツ化**という観点では、本動画の手法はテクスチャ不要でパラメータ化された三角形/矩形/円マスクを Material Function 化しておけば、警告アイコン・ヒットマーカー・ダメージ数値の背景バッジ・SP/OC ゲージの装飾パーツなど、**HUD 寄りの軽量図形パーツを個別テクスチャなしで量産できる**という利点がある。既存ドクトリンの「1粒バースト+カーブ駆動の器」原則とは別軸で、**「テクスチャアセット0個で幾何形状を作る」軽量化パターン**として活用余地がある
- METEO 系の SP 技テレグラフ（AOE の扇形/矩形範囲表示）は現状 DrawDebug 仮実装だが、本動画の矩形/円マスク手法をベースにした Material Function を作っておけば、Niagara/Decal 本番移行時に**同じ数式パターンでエッジのシャープさ・フェード幅をパラメータ制御**できる。特に円マスクは既存の Radial Gradient 定型と統合しやすい
- Length ノードのクランプ注意点は、既存の OC ジェムや他の矩形/多角形マスクを使うマテリアル実装で同種のバグ（中心が意図せず明るくなる）が起きていないか、実装時のチェックリストに加える価値がある
- 「目」パターンの図形差分合成は、敵アイコンやミニマップ用の簡易記号アイコンをテクスチャレスで作る際に転用できる可能性がある
