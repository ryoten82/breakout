## 概要

矩形と円形、2 種類のシンプルなポータルマテリアルを追加アセットなしで作る動画。共通する骨格は「ノイズテクスチャのピクセル化マスクで形状を作る → Step + Dynamic Material Parameter で開閉アニメーションを外部制御する → Cube Map（反射ベクトル）でポータル内部の別空間を表現する」の3層。Niagara 側では Particle Renderer と Mesh Renderer の使い分け、カーブによる開閉シーケンスの作り込みが後半の主題。

## 矩形ポータルの構築

1. マテリアル設定: Blend Mode = Translucent, Shading = Unlit, Two Sided
2. ノイズテクスチャを**ピクセル化**（doctrine 既存パターンの再利用と字幕内で明言。デフォルトのピクセル化レベルは 24）
3. Panner でこのピクセル化テクスチャをアニメーション（速度 0.1 / 0.2 ※推定）、出力値を ×0.1 で強度抑制
4. **RG チャンネルを個別に使用**: テクスチャの R/G チャンネルをそれぞれ水平（U）・垂直（V）方向のマスク制御に使う。UV から 0.5 を減算して中心基準に座標をシフトし、絶対値を取る
5. **Step + Dynamic Material Parameter でマスク範囲を制御**: R チャンネル＝水平方向の開き具合（最大値 0.5）、G チャンネル＝垂直方向の開き具合（0.4 に設定）。2つを乗算して矩形の基本形状マスクを得る
6. **エッジ発光**: 同じノード群をコピーし、Float パラメータ「edge width」（DMP 化、デフォルト 0.03）を加算した「一回り大きいマスク」を作る。大きいマスク − 小さいマスク でエッジ部分のみのマスクを抽出 → Emissive Color に乗算
7. **内部シーン**: Reflection Vector + Cube Map（システム提供の Cube Map テクスチャ）でポータル内部の異空間を表現。小さい方のマスクに乗算してエッジの発光と加算合成
8. Opacity には**大きい方のマスク**を使う（内部テクスチャとエッジ発光の両方をカバーするため。小さい方のマスクだとエッジの発光が透過されず見えなくなる、という失敗パターンが明示的に説明される）

## 円形ポータルの構築

- 骨格は矩形版と同一だが、マスク生成に **Radial Gradient**（Radius・Intensity 制御）を使う点が異なる
- ノイズのピクセル化に Panner は不要（放射方向の速度制御に **Vector To Radial Value + Radial Speed** を使用、速度は 1・1 ※推定）
- `1.0` との距離比較（`Distance` / 実質 `abs(1-x)` 相当）でマスクの濃淡を作る: 中心に近いほど 1 との差が小さく出力が暗く、エッジに近いほど出力が大きくなる分布
- 以降は矩形版と同じ Step + DMP による開閉制御、大小マスク差分によるエッジ抽出、Cube Map 内部合成、Opacity=大マスクの流れ
- ピクセル化レベルは 64 まで上げて調整（エッジのギザつきが強すぎたための補正、と説明）

## Niagara 側のアニメーション設計

### 矩形版
- Particle Renderer で開始。Spawn Burst 1回、Lifetime を長め（15秒）に設定
- 色は Particle Color 経由に切り替えて Niagara 側で制御可能にする
- **DMP を Particle Update でカーブ駆動**: R チャンネル（水平開閉）と G チャンネル（垂直開閉）を別々のカーブで制御し、**開始タイミングをずらす**ことで「まず水平に開き、続いて垂直に開く」という段階的な開閉演出を作る（R: key0.3で値0.3=最大、0.9から減衰。G: key0.5で値0.4=最大、0.8から減衰、さらに開始 key を0.3にずらして水平が先行するよう調整）
- **カメラ正対の限界と Mesh Renderer への切替**: Particle Renderer はデフォルトでカメラ正対（ビルボード）になるが、固定軸方向に向けたい場合は Alignment/Facing Mode を Custom + Particle Facing に設定できる。ただしこれでも横から見ると回転して見えてしまう問題があるため、動画では **Mesh Renderer（Plane メッシュ1枚）への切替を推奨**。Initial Mesh Orientation で X 軸を 0.25 に設定し、デフォルトの向きを補正

### 円形版
- 同様にカーブで DMP を制御。サイズは 0→0.3(値0.8)→0.9で減衰→0 という三段カーブ
- **エッジ幅もカーブ化**（矩形版はエッジ幅を固定値のままにしていたのに対し、円形版では key0.3=0.5（最大サイズ到達時にエッジを太く）→key0.5=0.03（通常値に戻す）→key0.8=0.03維持→key1.0=0.5（再び太く）という4点カーブで「開閉の瞬間にエッジを強調する」演出を追加。動的に見える効果として明示的に評価されている

## 新規性のある技術情報（既存ドクトリンとの比較）

`fx_technique_doctrine.md` および既存ポータルノート（h-gp4l1oIbU）と比較して未収録の技術:

- **Step + Dynamic Material Parameter による形状マスクの開閉制御パターン**: DMP の値をそのまま Step の閾値として使い、RG 各チャンネル（= 水平/垂直、または半径）を独立制御することで矩形/円形の「開き具合」を外部からアニメーション可能にする設計。doctrine の「グロー勾配」節とは別軸の、**形状そのものを DMP で開閉させる**パターンとして追記候補
- **大小2枚のマスク差分でエッジのみを抽出する手法**（「同じマスク生成ロジックをコピーし、パラメータを1つだけ拡張した版を作って差分を取る」）は h-gp4l1oIbU のエッジ手法（Vector To Radial Value + Radial Gradient 単体）とは異なるアプローチで、より汎用的（矩形・円形どちらにも同じロジックが使える）
- **Reflection Vector + Cube Map によるポータル内部シーン表現**: doctrine未収録。ポータル内部に「別空間が見える」表現を、専用シーンキャプチャではなく既存 Cube Map テクスチャの反射ベクトルサンプリングだけで安価に済ませる手法
- **開閉タイミングをチャンネルごとにずらして「水平→垂直」の段階的シーケンスを作る**カーブ設計、および**エッジ幅を独立したカーブで別テンポで変化させて動きに変化をつける**という2点は、doctrine「カーブは全キーAuto、出現はオーバーシュート」節を補強する具体例
- **Particle Renderer のビルボード制約と Mesh Renderer への切替判断**（Alignment/Facing=Custom+Particle Facing でも横から見ると破綻するため、固定平面が必要な場面では最初から Mesh Renderer + Initial Mesh Orientation を使う）は doctrine 未収録の実務的判断基準

## SCRAP BLITZ UEへの応用メモ

- **ワープ/転送ギミック**への適用は h-gp4l1oIbU 同様に有効だが、本動画の手法は**マテリアルのみで矩形/円形どちらの形状にも対応できる汎用性**が強み。ステージ形状に合わせてリスポーン地点（円形）とエリア間ゲート（矩形）を同一ロジックの使い回しで作れる
- **DMP カーブによる「水平→垂直」段階開閉**は、ボス戦フェーズ切替やステージギミック起動時の「ゆっくり形が現れる」演出に転用しやすい。2.5D 固定カメラでは矩形ゲートが画面に正対しやすく相性が良い
- **Cube Map による内部シーン表現**は、専用の Scene Capture Component を使わずに「ポータルの向こうに何かがある」感を安価に出せるため、実験的な導入コストが低い。既存の Skybox/環境 Cube Map を流用できれば追加コストほぼゼロ
- **Mesh Renderer + Initial Mesh Orientation** の判断基準（横から見た破綻を避けるため固定平面が必要ならメッシュ化）は、OC ジェムのビルボード問題（`setup_scrapblitz_ocgem_level_instance_overrides.md` 系の既存トラブル）と同種の教訓であり、今後 UE 側で平面ポータル/ゲートを実装する際は最初からメッシュ前提で検討すべき
