## エフェクト構築手順（工程順）

1. **[01:40]-[01:56]** テクスチャ準備：圧縮設定は「アルファ以上」（※推定：正しくは **Alpha (BC4 等、アルファチャンネル保持系)** の意図と思われる。字幕からサイズ数値は判読不可）。マテリアルパラメータは「パワー」を持ち、光の伸び方の鋭さを調整
2. **[02:00]-[02:17]** 新規エミッターをEmpty（空テンプレート）から追加、名前をリネーム
3. **[02:32]** マテリアルを設定
4. **[02:37]-[02:48]** Spawnモジュール追加：1回限りの生成なら **Spawn Burst Instantaneous**、継続生成なら **Spawn Rate** を選択（本編は3個/burst相当の値を入力）
5. **[02:52]-[04:10]** Initialize Particleモジュールで初期値設定：
   - 寿命：Random Range（Float）モードに切り替え、秒数入力
   - 初期カラー：Direct Set（ダイレクトセット）でカラーピッカーから選択。使用色は「微妙に空色が入った白」
   - 初期サイズ：**Random Non-Uniform** モードに切替 → X=横幅・Y=縦を別々に調整可能に
   - 初期回転値：ランダムでよい（厳密な調整不要）
6. **[04:10]-[05:15] 本題：原点（ピボット）位置の変更**
   - デフォルトはスプライト中心に原点があるため、縦方向に拡大すると中心から両方向に均等に伸びる。回転も中心軸周りになる
   - 原点をテクスチャの**先端**に移動すると、拡大時に「中心から放射状に伸びる」動き・「原点を起点に回転する」動きに変わる
   - 設定箇所：**Sprite Renderer** 詳細パネル → **Pivot in UV Space**（デフォルト0.5, 0.5＝中心）。UV座標系での意味（0,0が左上等）を踏まえて先端に相当する値（例: 0.5, 1.0 等、動画では具体的な理想座標を算出して入力。字幕からは正確な数値を判読不可）に変更
   - 変更後、中心から放射状に伸びる光の筋の見た目になる
7. **[05:19]-[05:57] 回転アニメーション追加**：Particle Update に **Sprite Rotation Rate** モジュールを追加。デフォルトは固定値1つだが **Random Range Float** に切替えると最大/最小の範囲内でランダム速度回転。本編は「1秒間に最大30°回転」程度の動きに設定
8. **[05:57]-[07:32] サイズの経時変化**：Particle Update に **Scale Sprite Size** モジュールを追加
   - デフォルトは縦横同比率拡大。今回はX/Yを別カーブにしたいため **Non-Uniform Curve** モードへ変更
   - Curve Editorで X（横）・Y（縦）を別々に編集：X軸選択でXのみ表示等の切替可
   - キーフレーム選択→アンカーアイコンでベジェ的な補間に変更可能。カーソルアイコンで選択グラフに自動フォーカス
   - 横（X）: だんだん細くなる動き（時間軸0で1、時間軸1で0.75）、カーブ状に補間
   - 縦（Y）: だんだん長くなる動き（初期0.3→最後1.0）、こちらはリニアのまま
9. **[07:44]-[08:56] 色・透明度**：Particle Update に **Scale Color** モジュールを追加
   - RGBを1.5倍にして明るさを上げる
   - アルファ値は **Float from Curve** モードに変更しCurve Editorで調整：0から始まり、山型（一度上がってまた下がる）の波形カーブ。ピーク時の透明度は約0.35
   - キーフレーム新規追加はマウスホイールクリック
   - 応用Tips：同エミッターを複製し色違い（白→水色等）にすることでバリエーションを作れる、と言及
10. **[08:56]-[09:42] 描画順（ソート）調整**：他アイテムとの重なり問題を解消。**Sprite Renderer の Sort Order Hint** に数値を入力（値が大きいほどカメラ手前に表示）。フラッシュ側を0→-1にすると他要素が手前に出るが副作用で白浮きが発生したため、対象を変更し**別エミッター（クリスタル）側のSort Order Hintを上げて手前表示**にする方針転換（フラッシュを奥に送るのではなく、他要素を手前に出す方が結果が良かった、という判断）

## 判断基準・コツ

- **ピボット移動が本編の核心技術**：Sprite Rendererのデフォルト中心ピボットのままだと、拡大・回転が常に「中心対称」になる。**光の筋（放射状ストリーク）を作るにはピボットをテクスチャ先端にずらす**ことで、拡大＝放射方向への伸び、回転＝先端を軸にした回転、に変換される。Beam Rendererやリボンを使わず、**Sprite Renderer 1枚 + Pivot in UV Space変更**だけで筋状の演出を実現している点が既存doctrineの「ビーム/光の筋」節（Ribbon Renderer + Beam Emitter Setup前提）とは異なるアプローチ
- X/Y非対称のScale Sprite Size（横は先細り、縦は伸長）を組み合わせることで、単なる拡大ではなく「光が奥から手前に伸びてくる」ような方向性のある見た目になる
- ソート問題の解決策として「問題のあるエミッター自身のSort Order Hintをいじる」のではなく「共演する別エミッターのSort Order Hintを調整する」方が結果が良かった、という試行錯誤の実例（唯一の正解ではなく現場判断で選んでいる）
- テクスチャ側の作り方（動画後半、[09:51]-[11:45]）：黒背景に白長方形を描き、変形（自由変形）で先端を細める形状に加工 → レイヤーマスクをグラデーション（白黒）モードにし、Shift押しながらまっすぐグラデーションをかけて先端をフェードアウトさせる → レイヤー塗りを60%に落とす → 別レイヤーで楕円選択+白塗り+ガウスぼかしを重ねてグロー感を追加、という2レイヤー構成（本体+グロー）

## SCRAP BLITZ UEへの応用可能性

- 汎用性言及（宝箱・扉・自爆漏れ光）はいずれもSCRAP BLITZ UEの世界観（廃品/機械オブジェクト演出）と親和性が高い候補。ギミック開放演出やアイテムドロップ時のワンショットVFXとして転用可能な軽量エフェクト
- ピボット移動によるSprite放射ストリーク手法は、Ribbon/Beamを使わない**最軽量な「光が広がる」表現**として、Pickup生成時のワンショットFXやOCジェム演出の付加要素に使える可能性がある（既存の`iDrsEp3AGWA_magic-orbs.md`のSort Order Hint多層構成と組み合わせ余地）

## doctrineとの比較（新規性チェック）

- fx_technique_doctrine v2.2の「ビーム/光の筋」項には「動画字幕は取得不可のため未参照」と明記されていた。本ノートでその字幕を確認できたが、**本動画が扱う「フラッシュ」はdoctrineが指すBeam Emitter（Ribbon Renderer + Absolute Start/End）とは別物**で、Sprite Renderer 1枚 + Pivotオフセットによる放射ストリークという、より単純な代替手法。doctrineの当該項目は差し替えではなく**併記に値する軽量版パターン**として扱うべき
