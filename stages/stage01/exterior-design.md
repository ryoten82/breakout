## ロケーション基本情報

**Act 1（factory）/ Stage 1 — 外周ヤード（工場外周・侵入導線）**

- Act テーマ：factory（確定 2026-05-18）／Act ボス：CRUSHER（戦闘は stage3）
- 役割：プレイヤーが最初に踏み込む工場群外周。ステージ末で**巨大な車両用入り口**から内部へ侵入する動線

## 確定方針（上位）

### スケール基準
- **主人公機体長 20m**（全キャラ共通）
- 背景・敵・プロップすべてこれに合わせて巨大化
- 現実参考から **2〜3 倍誇張**が必要（ミニチュアセット感の回避）
- ベルスク帯幅（Z ±380wu）と 20m スケールの比率は実装時に要確認

### 公式換算（2026-05-18）

- **1 wu ≒ 0.12 m**（既存プレイヤー全高 170 wu = 20m から逆算）
- **現実 m × 8〜10 倍 ＝ wu**
- 詳細・新規プロップサイズ目安・既存実測値は memory `project_scrapblitz_act_scale_aesthetic.md` 参照
- **各素材の具体サイズは仮実装時に違和感見ながら調整**（目安値は固定ではない）

### 世界観美学：「希望寄りの廃墟」
- **晴天・明るい色味・植物の侵食**（自然が取り戻している感）
- 完全廃墟・暗くじっとり系は**採用しない**
- 北極星「暗くなりすぎない」（仕様書 §5）と直接整合
- ガオガイガー的「AI に取られたがまだ取り戻せる」雰囲気

## 書割多層構成（既存 2 カメラ構造を活用）

### 前提：既存カメラ構成

| カメラ | 種別 | パラメータ | 担当レイヤー | 用途 |
|---|---|---|---|---|
| `bgCamera` | Perspective | FOV 5（超望遠・近 ortho）／pos (0, 500, 6000) | **layer 1** | 遠景書割（空・山岳・工場群シルエット） |
| `camera` (main) | Orthographic | ORTHO_H=700 | **layer 0** | プレイ平面・中景プロップ・近景 |

レンダ順：bgCamera → main。bgCamera は X 追従するが超望遠なのでパララックス効果は弱め＝「遠景の安定感」が出る。

既存実例：
- `buildBackgroundElements()` 奥の柱・ネオン群 = `z=-1100` / layer 1（bgCamera で描画）
- `buildBackWallPillars()` 廃工場柱組 = `z=-380` / layer 0（main で描画・ベルスク帯の奥壁）

### 既存 z=-380 奥壁（柱組）の扱い

外周ヤードでは内部用の柱組は使わない：

- **A**：完全に非表示（exterior 起動時に柱組グループを `visible=false`）
- **B**：別装飾に差替え（外壁シルエット・フェンス等を同じ z=-380 に置く）
- **推奨：A**（プロト段階）。内部移管時に柱組は Stage 2 専属になるので、Stage 1 では単純に隠す

### 光源

屋外晴天想定：

- `DirectionalLight`（太陽光・斜め下向き・暖色寄り）— 強度高め
- `AmbientLight`（青空からの拡散光）— 強度高めで「明るく開けた絵」を担保
- 既存の `applyBodyEmissive` 等のキャラ表示と干渉しないか実装時に動作確認

### スケール感の検算（20m = 170 wu 基準）

- 層 1 空 4000 wu 高 = 470m → 視野の上限まで青空
- 層 2 山岳 1000 wu 高 ≒ 118m → 遠景山として違和感なし
- 層 3 工場群シルエット 1500 wu 高 ≒ 177m → 巨大工場（実物 60-100m を 2 倍誇張）
- 層 4 球状タンク 直径 340 wu ≒ 40m → 大型タンクとして OK
- bgCamera は FOV 5 でほぼ ortho、Z 距離による見かけサイズ差は小（実装時に調整）

## セクション境界の表現

旧案：黄黒帯（廃工場立入禁止標識）。
新方針：**路面の質感変化（舗装 → 剥げ密度増 → 植生密度増）**で代替。黄黒帯は工業地帯らしさで違和感ないが、外周ヤード（屋外）では植生密度のグラデの方が「希望寄りの廃墟」美学と合う。

両案併用も可（黄黒は工場入口直前の警告として残すなど）。

## ステージ間遷移演出（transition.js 最小仕様・2026-05-18 確定）

### 役割分担

| ファイル | 役割 |
|---|---|
| `clear.js`（既存） | 「STAGE CLEAR」汎用シグナル＋オーバーレイ DOM | 単純な暗転＋テキスト |
| **`transition.js`（新規）** | Stage 1 → Stage 2 専用の演出シーケンス（カメラパン＋暗転＋STAGE 2 テロップ） |

`clear.js` は触らない（汎用 STAGE CLEAR として残す）。`transition.js` はそれを呼んだ後の「次ステージへの導入」を担当。

### API

```js
// transition.js
export function initTransition(deps);
// deps: { camera helpers (setCamRightLimit/getCamRightLimit) }

export function triggerStage1To2Transition();
// W4 全滅検知時に index.js（stage01）から呼ぶ

export function tickTransition();
// メインループから毎フレーム呼ぶ（フェーズ進行）

export function isTransitionActive();
// プレイヤー入力凍結判定用
```

### フェーズ機械

| フェーズ | 持続 | 内容 |
|---|---|---|
| `idle` | — | 待機 |
| `panning` | 60F (1.0s) | カメラ右端を x=3950 へ強制的に動かす（`setCamRightLimit(3950)`）。プレイヤーは置き去り |
| `fading` | 30F (0.5s) | 黒オーバーレイを 0 → 100% にフェードイン |
| `showing-text` | 90F (1.5s) | 「STAGE 2」テロップ表示（フェード完了状態を維持） |
| `done` | — | 完了。プロト段階では何もしない（F5 リロード待ち） |

合計：約 3 秒（180F @60fps）

### 既存資産の使い方

- **カメラパン**：`setCamRightLimit(3950)` で右端ロックを上書き。`camTargetX` はデッドゾーン追従で勝手に右端 = 3950 に寄せられる
  - 補足：プレイヤーは置き去り（W4 全滅後だから OK）
  - パンスピードはデッドゾーン式の自然追従で表現
- **暗転＋テロップ**：`clear.js` のオーバーレイ DOM を流用 or 別 DOM を新規作成
  - 推奨：別 DOM 新規（`#stage-transition-overlay`）。clear.js と独立にすると将来 Stage 2→3 等で再利用しやすい
- **プレイヤー入力凍結**：`isTransitionActive()` を index.html メインループから参照。`true` なら `processAttackInput` 等をスキップ
  - プロト段階では実装省略可（W4 全滅後は敵もいないので暴れても影響なし）

### tickTransition の実装スケッチ

```js
let _phase = 'idle';
let _frame = 0;
let _overlayEl = null;

const TARGET_X = 3950;
const PAN_FRAMES = 60;
const FADE_FRAMES = 30;
const TEXT_FRAMES = 90;

export function triggerStage1To2Transition() {
  if (_phase !== 'idle') return;
  _phase = 'panning';
  _frame = 0;
  setCamRightLimit(TARGET_X);  // 右端強制
}

export function tickTransition() {
  if (_phase === 'idle' || _phase === 'done') return;
  _frame++;
  if (_phase === 'panning' && _frame >= PAN_FRAMES) {
    _phase = 'fading';
    _frame = 0;
    ensureOverlay();
    _overlayEl.style.opacity = '0';
    requestAnimationFrame(() => { _overlayEl.style.opacity = '1'; });
  } else if (_phase === 'fading' && _frame >= FADE_FRAMES) {
    _phase = 'showing-text';
    _frame = 0;
    _overlayEl.textContent = 'STAGE 2';
  } else if (_phase === 'showing-text' && _frame >= TEXT_FRAMES) {
    _phase = 'done';
  }
}
```

## 工場稼働状態と植生密度のエスカレーション（2026-05-18 確定）

Act 1 全体で「廃墟 → 取り戻されつつある」の物語性を演出するため、Stage 1/2/3 で**稼働度を段階的にエスカレート**、対比として**植生密度は段階的に減少**させる。

| Stage | 稼働状態 | 植生密度 | 雰囲気 |
|---|---|---|---|
| **Stage 1 外周ヤード** | **見た目は完全停止**（動的要素なし） | **ちょこちょこ見える**（舗装の割れ目・植物が突き破る） | 廃墟感が一番強い／自然が取り戻してる感 |
| **Stage 2 工場内部** | **何か稼働しているかも？的なものが見え隠れ**（コンソール LED 点滅・遠くで微かに動く何か） | **たまーに見える程度**（屋内なので植生は少ない・自然光が差す箇所のみ） | 不穏な気配・敵活動の予兆 |
| **Stage 3 工場深部** | **稼働状態**（蒸気漏れ・換気扇回転・警告灯点滅・煙突から薄煙・量産ライン稼働） | **ほぼなし**（深部なので植生侵食が及ばない） | 敵活動本格化・ボス戦の舞台 |

### Stage 1 の具体（本ファイルスコープ）

**動的要素：なし**（プロト実装でも動かさない。書割は静止画）

**植生要素（ちょこちょこ）**：
- 舗装の割れ目から生える草（小プロップ・近景に散在）
- 植物が突き破る箇所（路面剥げの中・特に Stage 境界近く）
- 樹木の幼木 1〜2 本（中景・絵のアクセント）
- 蔦の絡まりは控えめ（外壁・球状タンクの根元など）
- 量：「侵食してるね」と分かる程度。**主役にはしない**

### Stage 2/3 の動的要素（本ファイルでは概要のみ・詳細は各ステージ設計時）

- Stage 2：コンソール LED 点滅／遠景で微かに動く何か／自然光が差す位置に植生少々
- Stage 3：蒸気漏れ配管／巨大換気扇回転／警告灯点滅／煙突から薄煙／背景奥に動く量産ライン

## 設計論点（参考資料部屋ハンドオフから）

- **「奥の工場群」の見せ方**
  - bgCamera（Perspective・FOV5）でどこまで深度が出せるか／実装時に確認
  - シルエット重視（細部省略）か、ディテール込みか
- **植生の入れ方**
  - 舗装の割れ目から生える草・蔦／木の幼木／苔
  - 量：「侵食してるね」と分かる程度・主役にしない
- **車両用入り口の演出**
  - **最初から開放状態で固定**（2026-05-18 確定・アニメなし）
  - 暗い内部が見えている（次シーンへの誘導）
  - 余裕が出たら polish 要素として動的演出追加（蝶番のきしみ・微振動・スポットライト等）
- **CRUSHER との関係**
  - ボスは Stage 3 だが、ここから建物の影に CRUSHER のシルエットを見せて伏線にする選択肢あり
- **工場の稼働状態**
  - 完全停止／部分稼働／敵に乗っ取られて勝手に動いている — 要決定
- **メーカー世界観との絡み**
  - EVOL / ヤナギメカニクス / 近江重工 等のうちどこの工場か（仕様書 §5 系）

## 楽しさのチェックポイント

- 敷地入口で「これから工場に乗り込む」高揚感が出るか
- 奥に見える工場群シルエットで「廃工場の威容」が伝わるか
- 植生侵食で「希望寄りの廃墟」雰囲気が出るか（暗くなりすぎていないか）
- 巨大車両用入り口に寄っていく時の「踏破した」達成感
- 屋外光の温かさ vs 後の内部の照明でコントラストが効くか
