# セーブシステム設計

## 背景・きっかけ

ユーザー発言：

> データセーブの仕様はしっかり考えておきたい。
> ローグライトでもあるのでセーブのタイミングは重要だと思う。
> アイテムの利確や不正取得は避けたい。

仕様書本体の現状記載：
- §15: 「解放フラグは `localStorage` で永続保存」（実装ヒントのみ）
- §22 注釈: 「ギアスコアはセーブデータに保持」（保存対象の言及のみ）
- §29 関連: 「セーブデータ破損対策（バージョン管理・バックアップ）」（将来課題として）

→ **セーブのタイミング・形式・利確/不正取得対策は未定義**。本トピックで方針を固める。

## SCRAP BLITZ のデータ階層（前提整理）

| 階層 | 内容 | 性質 |
|---|---|---|
| **永続資産** | チップ・CR・キャラ解放・恒久強化・ギアスコア | ラン跨いで保持 |
| **ラン状態** | HP・SP・OC ビルド・進行位置・ラン中チップ取得 | ラン終了でリセット or 永続資産へ確定 |
| **設定** | キーコンフィグ・音量・解像度等 | プレイヤー設定 |

## 論点

1. **セーブのタイミング**: いつ書き込むか（オート / 手動 / 両方）
2. **利確対策**: ラン中のチップ取得を「失敗したらセーブ前に戻す」プレイを防げるか
3. **不正取得対策**: ファイル直接編集による資産水増しをどこまで防ぐか
4. **クラッシュリカバリ**: アプリ強制終了でラン継続できるか

## 案

### 案A: 完全オートセーブ・1 スロット（Hades / Slay the Spire 式）

- **手動セーブ不可・常時上書き**
- セーブタイミング：
  - 永続資産変更時（チップ取得確定 / CR 入手 / キャラ解放 / 恒久強化購入）
  - ラン状態変化時（マーカーウェーブ後 / 中ボス撃破後 / ターミナル帰還時 / 死亡確定時）
  - クラッシュリカバリ用：戦闘中も低頻度で進行点を上書き
- 利確対策：**構造的に不可**（前のセーブに戻れない・複数スロットなし）
- 不正取得対策：チェックサム・難読化程度（シングルプレイなので過剰防御しない）

### 案B: チェックポイント式（ターミナル / マーカーウェーブのみ）

- セーブは特定ポイントのみ
- 戦闘中はセーブされない（クラッシュでその戦闘の進行は消える）
- 利確対策：ラン中チップは「持ち帰り成功時」まで確定しないので利確不可
- クラッシュリカバリ弱い

### 案C: 案A + ラン状態と永続資産の二層分離

- 物理ファイルは 1 ファイルだが、内部構造で永続資産とラン状態を明示分離
- ラン状態は「ラン終了 / 死亡時」に永続資産側へ**確定マージ**
- 永続資産の変更は ACID 風（途中で電源切れても整合性保つ）
- 案A の利確不可性 + 復旧の堅牢さを両立

## トレードオフ・整合性チェック

| 観点 | 案A | 案B | 案C |
|---|---|---|---|
| 利確不可 | ◎ | ○ | ◎ |
| クラッシュリカバリ | ○ | △ | ◎ |
| 実装コスト | 中 | 小 | 中〜大 |
| 不正対策（軽防御） | ○ | ○ | ○ |
| デザインの綺麗さ | ○ | ○ | ◎ |

**整合性チェック**
- §13.3 死亡ペナルティ（7割没収）: 死亡時にセーブが入る前提なので案A/C と整合（案B は戦闘内死亡を扱えない）
- 北極星1（手触り・ノイズ最小化）: いずれも整合（セーブ操作自体がプレイヤーに見えない方が良い）
- 将来 Unreal 移行: Save System + Steam Cloud に乗せやすい構造（案C が綺麗）

## 不正取得対策の温度感

完全防御は無理（シングルプレイのローカル保存は原理的にチート可能）。**現実的な落としどころ**：

- ✅ チェックサム / ハッシュ署名（軽い改竄検知）
- ✅ JSON を Base64 + 軽い難読化（カジュアル改竄を抑止）
- ❌ サーバー検証（オンライン機能の時のみ・ローカル単独では不要）
- ❌ DRM レベルの保護（コミュニティ MOD への配慮 + コストに見合わない）

**方針**：「**普通の人がメモ帳で開いて編集できない**」程度で十分。MOD コミュニティが立ったらむしろ歓迎。

## 現時点の傾き

**案C（案A + 二層分離）を推奨叩き台**。理由：

- 利確を構造的に不可能にできる（案A の良さを継承）
- ラン状態と永続資産を分けることで、ラン失敗時の確定処理が綺麗
- クラッシュリカバリが堅牢（戦闘中に強制終了されても次回起動でラン継続）
- 将来 Unreal Save System / Steam Cloud に移行しやすい

実装段階：
- Three.js プロト：`localStorage` で十分・JSON 構造を二層化
- Unreal 移行：SaveGame オブジェクトを永続資産用とラン状態用に分割
