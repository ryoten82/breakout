# ゴア・スクラップシステム — 雑魚仕様（敵死亡処理 + 部位破壊演出）

## 背景

[親トピック](gore-scrap-system.md) のうち、**現フェーズ（Phase 2.x）の既存資産で実装可能な範囲**を切り出した実装着手用トピック。

中ボス・大ボス仕様・Unreal Chaos / Niagara 関連は親トピックに残し、Phase 3 以降で詰める。

### 重要な前提（2026-05-16 ユーザー指摘）

**現状、敵の死亡処理がほぼ未実装**：
- memory に記載通り：「HP 0 で `damage-system` の死亡判定が hp 回復 + 演出のみ実行し、ダミーが復活する」サイクル
- つまり「敵を倒す」という体験自体がまだプロト化されていない

→ **「敵を本当に倒す」実装をする瞬間 = ゴア・スクラップ演出を組み込む瞬間**。
後付けでなく、**死亡処理の初回本実装でゴア・スクラップを一体設計する**のが自然。

この観点が抜けていると、後から死亡演出を差し込むことになり、ステート遷移の整合性で苦労する可能性が高い。

## Phase 2.x で着手可能な範囲

### 演出フロー（雑魚のみ）

```
HP 0 になる
   ↓
黒くフェード開始（3〜4 秒）← 新規 dead 系ステート
   ↓
（A）何もせず → フェード完了で消滅
   ↓
（B）フェード中に殴り続ける
   → 一定確率でパーツがバラバラに
   → パーティクルは黒（オイル）
   → パーツ分類：頭 / 左腕 / 右腕 / 胴体上半分
   → ダウン確定 → その場で爆発・消滅
   → 各パーツは一回バウンドして消える
   ↓
（C）バーストダウン（lv06 系ヒット時 or 大ダメージ）
   → きりもみ吹っ飛び（既存 down_chou_* 流用）
   → トレイル放出（オイル黒）
   → 爆散
```

## 実装スコープの再定義（2026-05-16 更新）

このトピックは単なる「演出追加」ではなく、**敵死亡処理の本実装**を含む。
具体的なスコープ：

| 範囲 | 内容 |
|---|---|
| **敵死亡処理の本実装** | HP 0 → 死亡判定（hp 回復しない）→ 死亡系ステート遷移 → 消滅まで |
| **ゴア・スクラップ演出（雑魚版）** | 上記死亡フローの中で発生する黒フェード + パーツ破壊 + バーストダウン |
| **ダミー復活ロジックの扱い** | 開発用ダミーには別フラグで復活モードを残す（テスト効率維持のため・`SB.DUMMY_REVIVE = true` 等） |

→ 「死亡実装」と「ゴア演出」を分離せず、**同じ作業として進める**のが自然。
分離すると、後で死亡演出を差し込む時にステート遷移整合が崩れやすい。

## 既存資産との対応関係

| 要素 | 既存資産 | 新規実装 |
|---|---|---|
| HP 0 検出 | ✅ `damage-system.js` 既存 | **死亡判定の本実装**（hp 回復をやめる分岐追加） |
| 黒フェードステート | 🟡 `dead state` 枠は救助システムで確保済（要拡張） | 黒フェード進行ロジック |
| フェード中の被ヒット判定 | ✅ `hit-engine.js` の判定で対応 | フェード中専用 dispatch |
| パーツ吹き飛び確率判定 | - | 確率ロジック追加 |
| 敵 mesh の部位分割 | 🟡 既存 mesh 構造による（要確認） | 必要なら分割追加 |
| 黒オイルパーティクル | ✅ パーティクルシステム既存 | 色設定 0x000000 系で対応 |
| パーツのバウンド処理 | ✅ 物理計算（vy / gravity）既存 | パーツ独立移動処理 |
| 爆散演出 | ✅ パーティクルシステム既存 | 粒数多めの放射パターン |
| トレイル | 🟡 既存トレイル機能の有無要確認 | 必要なら trail プリミティブ追加 |
| きりもみ吹っ飛び | ✅ `down_chou_start` / `down_wall_start` 既存 | 流用 |

## 派生論点の Phase 2.x 内回答（要相談）

親トピックの派生論点のうち、Phase 2.x で決める必要があるもの：

| 論点 | Phase 2.x で決める？ | 叩き台 |
|---|---|---|
| フェード中の被ヒット判定 | **要決定** | 殴れる・ノーダメ・パーツ吹き飛び確率判定だけ走る |
| パーツ吹き飛び確率 | **要決定** | 1 発 30〜50%（実プレイで調整） |
| バーストダウン発生条件 | **要決定** | lv06 攻撃ヒット時 |
| ドロップとの関係 | 後回し | 通常 CR ドロップと同じで OK |
| コンボカウンタ | 後回し | フェード中の殴りもコンボ継続 |
| パーツ別の挙動差 | 後回し | 最初は全パーツ同じ挙動 |
| パーティクル色味 | **要決定** | 完全黒（0x000000）or 黒に少し青味（0x0a0a1f 等） |
| 画面シェイク | 後回し | バーストダウン時のみ軽く |

## 実装手順（着手順序）

1. **敵死亡判定の本実装**（最初に必須）
   - `damage-system.js` で hp ≤ 0 検出時の分岐を「ダミー復活」から「死亡フロー」に切り替え
   - 開発用ダミーは `SB.DUMMY_REVIVE = true` フラグで復活モードを残す（テスト効率のため）
   - 死亡確定時：敵を「死亡系ステート」（黒フェード）に遷移させる

2. **dead 系ステートの拡張**
   - 既存 `dead state` 枠に黒フェードロジック追加
   - フェード時間：3〜4 秒（パラメータ化して `SB.GORE_CONFIG.FADE_DURATION` で調整可に）
   - フェード進行中：move 不可・既存ノックバック処理は引き続き効く・mesh は残る・色がフェード

3. **フェード中の被ヒット dispatch**
   - `hit-engine.js` に「敵が dead 系ステート時の追加処理」を追加
   - ヒット時：確率判定 → パーツ吹き飛び発火 or ノーリアクション
   - フェード中の hp はマイナスのままでも何もしない（既に死亡確定）

4. **パーツ吹き飛び処理**
   - 敵 mesh の構造確認（既に頭・胴体・腕で分かれているか）
   - 分かれていない場合は新規分割（プロト用 procedural box の組合せでも OK）
   - 各パーツに飛翔ロジック（vx / vy / vz + gravity + 1 回バウンド + 消滅）

5. **黒オイルパーティクル**
   - 既存パーティクル発火点を「フェード中のヒット位置」に流用
   - 色 0x000000 系・粒数多め・粘性表現で軌跡引きずり

6. **バーストダウン演出**
   - 「死亡 + lv06 ヒット」or「死亡 + 大ダメージ」で発火（要相談）
   - きりもみ吹っ飛び（`down_chou_start` 流用）+ トレイル + 爆散の連続演出
   - 黒フェード経由せず即時爆散（演出の特別感）

7. **消滅処理**
   - 黒フェード完了 → `scene.remove(enemy.mesh)` + dispatch list から削除
   - パーツ吹き飛び完了 → 同上
   - バーストダウン爆散完了 → 同上

8. **デバッグ機能**
   - `SB.GORE_CONFIG.FORCE_BURST` で常にバーストダウン発火
   - `SB.GORE_CONFIG.PART_BREAK_PROB` で確率調整
   - `SB.DUMMY_REVIVE` でダミー復活モード切替
   - スロー再生(T) でパーツ飛散の確認

## 検証ポイント（実装後）

- [ ] 黒フェード時間（3〜4 秒）が雑魚密集戦でテンポを損ねないか
- [ ] パーツ吹き飛び確率が「たまに見える」レベルになっているか（高すぎ・低すぎ）
- [ ] バーストダウンの絵が「ご褒美」として機能するか
- [ ] 黒オイル + 黒シルエットの色味が画面で見やすいか
- [ ] 複数敵を同時に倒した時にパーツが画面を埋めすぎないか
- [ ] バウンド 1 回後の消滅が自然に見えるか
